# Modulify Modules Guide

This guide explains how to create and register new modules in Modulify. It complements the Example Modules module in the UI.

## Folder structure (module anatomy)

```
Modules/
  <ModuleName>/
    app/Http/Controllers/
    Routes/web.php
    resources/views/
    database/
    module.json
```

What goes where:
- `Routes/web.php`: module routes under `/m/<moduleKey>` with auth + EnsureModuleAccess.
- `app/Http/Controllers`: controllers per module page/feature.
- `resources/views`: Blade views for module pages.
- `database/`: optional migrations/seeders for module-only data.
- `module.json`: module metadata + service provider registration.

## Step-by-step: create a module

1. Create the module: `php artisan module:make YourModule`.
2. Update routes in `Modules/YourModule/Routes/web.php`.
3. Add controllers under `Modules/YourModule/app/Http/Controllers`.
4. Add views under `Modules/YourModule/resources/views`.
5. Register the module in `modules` table (via seeder).
6. Register menus in `module_menus` table (via seeder or Admin Center).
7. Add and assign permissions (Spatie).

## Permissions (Spatie)

Each module should have:
- `access <moduleKey>`
- `<moduleKey>.view`
- `<moduleKey>.create`
- `<moduleKey>.edit`
- `<moduleKey>.delete`

Add these in `database/seeders/DatabaseSeeder.php` and sync to roles (admin, super-admin, etc.).

## Module record (modules table)

The `modules` table powers the Modules Dashboard and entry redirects. Add a record with:
- `key` (kebab-case, e.g. `example-modules`)
- `name` (human label)
- `description`
- `icon`
- `entry_route` (route name like `ex.dashboard`)
- `sort`, `is_active`

Seeder location: `database/seeders/DatabaseSeeder.php`.

## Sidebar menus (module_menus table)

Sidebar items are rows in `module_menus`:
- `label`
- `route_name`
- `icon`
- `sort`
- `permission_name`
- `group`
- `is_active`

Recommended: seed baseline menus in `DatabaseSeeder.php`, then allow Admin Center UI for runtime edits.

## EnsureModuleAccess middleware

File: `app/Http/Middleware/EnsureModuleAccess.php`

What it does:
1. Reads `moduleKey` from route parameters.
2. Confirms module exists and `is_active = true`.
3. Ensures user has `access <moduleKey>` permission.
4. Sets `activeModule` on the request for downstream usage.

## How routes load (nwidart/laravel-modules)

Each module has its own `RouteServiceProvider` (generated by Nwidart). It loads:
- `Modules/<ModuleName>/Routes/web.php` for web routes
- `Modules/<ModuleName>/Routes/api.php` for API routes (optional)

The module service provider registers routes and views so you can call:
- `view('modulename::page')`
- `route('prefix.name')`

## Related UI layout

- Module layout: `resources/views/layouts/module.blade.php`
- Modules dashboard layout: `resources/views/layouts/modules.blade.php`

These files control the shared shell and sidebar rendering for all modules.
